기존 방식 그대로 등록 / GitHub Pages 업로드

먼저 compare.html을 열면 A/B 시안을 비교할 수 있습니다.
index.html = A안(기본), concept-b.html = B안입니다.
B안을 최종 메인으로 쓰려면 concept-b.html을 index.html로 이름 변경해 업로드합니다.
두 시안의 작업 등록·업로드 방법은 같습니다.

A. 이번 전체 교체본 업로드
1) 기존 저장소를 먼저 내려받아 백업합니다.
2) ZIP 안 portfolio_design_v32 폴더의 '내용물'을 기존 저장소 루트에 넣습니다.
   index.html이 저장소 첫 화면에 보여야 합니다.
   portfolio_design_v32 폴더째 한 단계 안쪽에 넣지 않습니다.
3) 기존 저장소의 도메인 연결 파일(CNAME)이 있다면 그대로 유지합니다.
4) 기존 Pages가 main / root를 사용 중이면 그대로 커밋하여 배포합니다.
5) 새 저장소인 경우 Settings → Pages → Deploy from a branch → main → /(root) → Save.
6) 배포 후 새로고침해서 이미지·사이트 실행·상세 4종을 확인합니다.

압축파일 자체를 GitHub에 올려서는 웹페이지가 되지 않습니다. 반드시 풀어서 올립니다.
빌드·npm 설치는 필요 없습니다. 모든 경로는 저장소 하위 주소에서도 동작하는 상대 경로입니다.
.nojekyll 파일도 포함되어 있습니다.

B. 다음 작업을 등록하는 방법
1) projects 안에 작업 폴더를 만듭니다. 예: sample-project
2) 그 안에 thumbnail.jpg / main.jpg / project.json을 넣습니다.
   파일명은 JSON에 적힌 이름과 실제 파일의 대소문자까지 같아야 합니다.
3) projects/projects.json 배열에 "sample-project"를 추가합니다.
   배열에 놓은 순서가 전체 작업 목록 순서입니다.
4) 해당 폴더와 목록 JSON을 GitHub에 업로드합니다.
   홈페이지 HTML·카드 코드나 data/projects-data.js를 따로 고칠 필요가 없습니다.
5) 웹페이지를 새로고침하면 폴더 JSON을 읽어 목록과 상세에 반영합니다.

C. 대표 작업 롤링에도 표시하기
project.json에 다음 항목을 넣습니다.
  "featured": true,
  "featuredOrder": 1,
  "featureKicker": "WEB DESIGN"
featuredOrder가 작은 작업부터 나옵니다.
기존 4개는 작업 특성에 맞춰 실제 사이트·이미지형 상세 히어로·프로모션을 구성했습니다.
새로 등록하는 작업은 thumbnail에 지정한 이미지를 정면 프레임으로 표시합니다.
썸네일의 내용이 화면에 잘 맞도록 가로 이미지(예: 1600×960px)를 권장합니다.
자동 전환은 5초입니다. 마우스를 올리거나 클릭해도 계속 움직입니다.
일시정지 버튼·키보드 읽기·화면 밖 이동·다른 탭·모션 줄이기 설정일 때는 멈춥니다.
프로젝트를 대표 배너에서 빼려면 featured를 false로 바꿉니다.
전체 작업 목록에는 계속 남습니다.

D. project.json 예시
{
  "id": "sample-project",
  "projectName": "새 프로젝트",
  "title": "새 프로젝트",
  "type": "WEB DESIGN · PUBLISHING",
  "category": ["web"],
  "role": "웹디자인 · 퍼블리싱",
  "tools": "FIGMA · PHOTOSHOP · HTML · CSS · JAVASCRIPT",
  "thumbnail": "thumbnail.jpg",
  "mainImage": "main.jpg",
  "imageAlt": "새 프로젝트 메인 화면",
  "link": "",
  "overviewTitle": "OVERVIEW",
  "overviewText": "작업 목적과 제작 범위를 적습니다.",
  "workPointTitle": "WORK POINT",
  "workPointText": "구성·디자인·구현에서 맡은 부분을 적습니다.",
  "featured": false
}

분류: web = 웹사이트 / ecommerce = 쇼핑몰 / detail = 상세페이지 / graphic = 프로모션·그래픽
이미지를 여러 장 넣으려면 "images": ["main.jpg", "view-02.jpg", "view-03.jpg"]를 추가합니다.
실행할 웹사이트가 같은 작업 폴더의 site에 있다면 "link": "site/index.html"로 적습니다.
외부 사이트는 https://로 시작하는 전체 주소를 적습니다.
기존 JSON의 link, thumbnail, mainImage, overviewText, workPointText 필드도 그대로 읽습니다.
기존 작업 19개에 등록되어 있던 추가 이미지와 기여도 정보는 유지됩니다.

E. PC에서 직접 확인하기
처음 받은 ZIP은 index.html 더블클릭으로 확인할 수 있습니다.
새 작업을 추가한 뒤에도 더블클릭 방식으로 확인하려면 Python이 있는 환경에서
프로젝트 루트에서 아래 명령을 한 번 실행합니다.
  py tools/sync_projects.py
이는 로컬 미리보기 캐시만 갱신합니다. GitHub 호스팅에서는 JSON을 직접 읽습니다.

또는 프로젝트 루트에서 아래 명령을 실행하고 브라우저로 http://localhost:8000 을 엽니다.
  py -m http.server 8000

F. 코링클 이미지형 상세와 원본 교체
코링클 상세는 첨부한 JPG 이미지형 디자인을 사용합니다.
hero-butter.jpg / hero-bulgogi.jpg / hero-chili.jpg는 이번에 제공한 메인 이미지 원본입니다.
받은 JPG 파일을 자르거나 다시 압축하지 않고 그대로 사용했습니다.
thumbnail.png는 같은 이미지 3종을 모은 기본 썸네일입니다.
project.json의 heroImages 배열에는 label / image / width / height / background가 있습니다.
이 배열은 메인 롤링·작업 목록·상세 표지에 공통으로 적용됩니다.
메인 이미지만 교체할 때는 hero JPG를 교체하고 실제 width / height를 함께 갱신합니다.
기존 폴더·project.json·projects.json 방식은 그대로이며 일반 작업은 thumbnail / mainImage만 등록해도 됩니다.
로컬 더블클릭 미리보기도 갱신하려면 E의 sync_projects.py를 실행합니다.

긴 상세 4종은 메인 이미지와 별도로 유지됩니다.
아래 네 파일은 같은 이름으로 교체하면 됩니다. JSON·HTML을 다시 만들 필요가 없습니다.
  projects/kordetail/main.jpg
  projects/kordetail/sweet-bulgogi.jpg
  projects/kordetail/chili-garlic.jpg
  projects/kordetail/trio.jpg
긴 상세는 본문 폭에 맞춰 표시됩니다(PC 최대 1040px, 모바일은 본문 너비).
현재 업로드된 축소본 대신 실제 작업 원본을 사용해야 긴 상세의 글자를 선명하게 읽을 수 있습니다.
